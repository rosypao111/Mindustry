# 数据字典与汇总口径

主CSV来自接受版本的实际原生执行。`run_id` 是逻辑路线，`seed` 是独立样本单位，批次、窗口和重复执行都不能当作新的独立样本。两个策略、两条链分别报告。

| 字段 | 含义 |
|---|---|
| `source_artifact` | 实际阶段CSV；同目录事件文件记录原始事件 |
| `source_run_id` / `source_chain` | 原始物理执行标识；复用A前缀时可以与逻辑路线不同 |
| `reused_prefix` | 是否复用同种子、同策略、同输入的既有A阶段；不增加独立N |
| `seq` | 对应CSV内从1开始连续递增；不同类型CSV各自编号 |
| `journal_*_seq` | 指向同一实际阶段 `.events.csv` 的事件序号；不是当前汇总CSV的行号 |
| `step` / `sim_seconds` | S为固定60步/秒，均相对本阶段；路线时刻需加之前完成阶段的时长 |
| 空单元格 | 不适用、未达成或分母为零；不能自动填成0 |

## 批次日志

`batch` 从1开始，表示实际波次调用，不把单位数量当作批次数。`native_wave` 保留原生波号。`spawn_step` 到 `terminal_step` 的差除60为 `duration_seconds`；未清批次的终点是阶段结束，标记 `censored=true`。`actual_units` 为该调用实际加入的敌方单位数，`terminated_units` 追踪首次死亡或终止，避免重复死亡计数。封口且全部终止才算清除。

`tier` 的early/mid/late按实际批次1–10、11–20、21起划分。原生胜利波30只生成1–29批。阶段RMCT先对该次运行的批次时长取平均，再在组内对运行等权平均。零批次有效，但RMCT与η为空。

## 5分钟窗口日志

必须先筛选 `scope`，以下记录不能混在一起求和：

| scope | 用途 |
|---|---|
| `window` | 全窗口的缺弹、停机、治疗、电能和施工时间汇总 |
| `item` | 单物品供给、需求、缺口、实际扣料和订单余额 |
| `facility` | 按设施类型拆分的生产门控与停机；是总量的拆分 |
| `facility_supply` | 按产出设施拆分的真实产量；不是额外供给 |
| `facility_energy` | 按设施拆分请求和获得的电能；不是额外电能 |

窗口为阶段相对时间 `[300k,300(k+1))`，末窗按实际长度输出。端点恰好发生的点事件可有零时长边界窗，不求其速率。区间量按重叠长度积分，点事件归入其所在窗口。

`supply` 是钻头、加工厂和单位采矿的真实产出；传送、核心收货、跨阶段带入不再计产出。`full_demand` 是生产门控下满载加工/造兵/交战炮塔需求加实际建造扣料。`construction_paid` 是其实际施工部分。`flow_gap=max(0,full_demand-supply)`；`net_shortage_core` 再扣 `opening_core_stock`。核心口径未含工厂、传送带和单位缓冲。`due_unpaid_end` 是窗口末到期建设余额，不能跨窗口相加；阶段末余额与窗口最大余额分别报告。

`threat_turret_seconds` 和 `empty_turret_seconds` 是多座炮塔累计的炮塔·秒；`empty_fraction` 的分母是前者。多个设施累计的设施·秒可以大于窗口长度。`missing_item_seconds`、`missing_liquid_seconds`、`power_loss_seconds`、`zero_efficiency_seconds`、`efficiency_loss_seconds` 都在“想生产”的门控下统计，彼此可以重叠，不能当成互斥分类求总停机。堵塞与睡眠另列。缺电折损是供电不足的积分，不等于断电墙钟秒数。

`repair_effective_hp` 是实际有效治疗HP；`repair_energy` 是原生修复设施实际获得的游戏电能单位；`repair_material_paid` 为实际消费。`rebuild_paid` 为敌方战损重建实际物品扣料。`rebuild_equivalent` 用铜0.5、铅0.7、石墨1、钛1、硅0.8加权，不等于建造工作量。

扩产、布防、战损重建在开工时分类。`*_seconds` 是原生施工执行时间，`*_fraction` 是三类施工时间之和中的份额，不是整个阶段的时间比例；无施工时为空。多施工单位可能同时施工。绝对时间与暴露时间归一化敏感性分开，不能把早死造成的短暴露解释成改善。

## 阶段、路线与统计表

`won` 表示该阶段实际达标，`core_lost` 表示玩家全部核心丢失。`terminal_reason` 保留原生胜负、修订首核目标与时限。里程碑 `*_seconds` 是本阶段真实发生时刻；路线首次时刻加上之前完成阶段时长。路线未达成用3L=16,200秒作单独标记的敏感性，不与真实达成时间混算。只有双方都实际达成的同种子才进入真实提前量。

核心失守率同时输出阶段到达分母和全路线分母。阶段B/C的RMCT、停机和里程碑均须查看到达数。`aux_stage_under_60min` 仅为辅助标签，不参与90分钟阶段上限的路线完成判定。

Wilson95%用于完成率；配对差按独立种子对重抽样2000次，固定统计随机种子，不对批次重抽样。`paired_stage_differences.csv` 的主方向为G0减处理组；`factor_effects.csv` 的完成率为处理减参考，时间负担指标为参考减处理；以各表字段和说明为准。置信区间不含多重检验校正。

C的 `effective_sim_seconds` 来自原生参与更新的Time.delta积分；`native_tick_seconds` 与墙钟另存。C的批次/窗口字段属于校准子集，不能冒充S的全量Q3/Q4。`C_vs_S_directions.csv` 分别比较阶段指标、路线完成和实际达成里程碑；全部失败的共同地板不构成方向一致。C五种子规则、S三十种子规则及实际贡献配对数均需满足。

`C_native_costs.csv` 与共同准备的 `C_preparation_payments.csv` 将每笔源扣除 `paid` 分解为实际消耗 `consumed_cost` 和搬运 `carried_resources`，逐笔满足前者等于后两者之和。研究支出全部属于消耗；发射扣除中的核心图纸属于消耗，携带库存属于搬运。例如源区扣铜3000可以对应图纸1000和搬运2000，不能称为消耗3000。费用分类表对所有有效路线等权平均，没有发生该笔支出的有效路线计0；未到达后续阶段导致的低支出不表示效率提高。

`C_conversion_events.csv` 保留合法一级工厂启用、本关科技前置暂缓和单位上限门槛的实际分支及原事件序号。`C_conversion_summary.csv` 的各列独立统计出现路线数，联合出现须查看其交集列；不能把不同种子的几项事件拼成一条因果链。初始地图规则、实际执行与实际达成的里程碑分别保留。
