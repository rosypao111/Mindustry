# C 原生战役校准实施草案（尚未冻结、无正式 C 样本）

按用户选择，从空白战役档实际完成原生前置关卡与研究，保存全部支付与运输记录。准备尝试不计入正式样本；失败尝试也保留。不得写入解锁、占领或目标标志来替代游戏过程。

准备目标是获得合法的链 A 入口和 B 的地图访问前置，不预先通关 fungalPass，也不以研究齐射、重构厂或 mace 作为准备目标。拟准备关卡为 groundZero、frozenForest、crateredBattleground、biomassFacility、ruinousShores。所有进入条件依原生科技树完成；具体已解锁内容、历史支付、各区实际库存及存档校验值在入口档完成时再冻结。结果 C-native-prerequisite-closure.json 是对全部 S 方块所需门槛的调查，不是提前赠送或提前解锁的清单。

校准样本拟从这个实际获得的共同入口档复制，每组每策略 5 个正式种子，1000–1004，同种子从相同入口状态开始。共同历史准备成本另表列出，不当作 40 个独立观察；测量期间的后续研究、发射及建造全部从真实库存扣除。入口档冻结前，不启动正式 C。两套策略与组别分表，C 数据不并入 S 主统计。

C 使用源构建 SDL 桌面客户端、原生战役、真实服务器与原生可变帧时钟，按实际 Time.delta 积分得到有效模拟时间，同时保存 state.tick 与墙钟及帧上限情况。不得用无界面固定步长快进冒充 C。原生战役会把部分地图核心替换为合法发射示意图核心、采用原生单位上限与携带容量，这些与 S 的差异须逐项列出；C 校准检验整体方向，不能把差异全部归因于某一研究费用。

研究使用 ResearchDialog 的原生付款方法，并先检查父节点及原生目标；发射使用 PlanetDialog、LaunchLoadoutDialog 的原生合法性与付款回调，逐项核对真实源余额与示意图/携带成本。评测地图开局玩家预置 Duo/Salvo 同样统一移除、不退款，仅对首次进入评测目标地图的原生预置建筑执行。

原生首访 fungalPass 存在科技循环：additive-reconstructor 要求原生攻下 fungalPass，而 S 策略原本通过 mace 反攻。C 的拟定合法适配是暂缓尚未解锁的重构厂订单，用同位置原生陆军工厂先生产 dagger，且严格保留原生单位上限；保留成军白名单、至少 8 单位/2000HP、实际 RTS 指令与 balanced/defensive 的先后规则。balanced 工厂保持原北向，未建重构厂时北侧可释放 dagger；defensive 保持其已规划的东侧出口，原生波次出现后反攻。所有组使用同一适配，不写科技状态、不刷单位；升级解锁后才可按原订单建造。此适配必须在正式 C 之前训练、验收并冻结，不能根据组间结果修改。

阶段 A/B 的原生胜利、C 首个敌核被毁及 L=5400 有效模拟秒保持题目口径。未通关、未进入及技术无效分别记录。科技循环及转换瓶颈须按第7.1章诊断，不能据此宣称工业建设整体无效。实时校准样本不足或方向不确定时，结论为证据不足。

拟冻结的 C 适配细节：未解锁的订单留在研究前沿表，不交给建造代理；已解锁订单按原相对顺序执行，几何坐标不变。全部当前可建订单完成后，优先支付一个所有原生前置均满足且可支付的研究节点，再为最早的可达节点采集缺料。必须由原生研究方法实扣，不能通过直接解锁跨越目标。首访 Fungal 的重构厂因本关占领门槛而暂缓；Dagger 已解锁才允许配置原生工厂。用于原生 CommandMode 教学目标的动作是本地玩家输入模式切换，目标完成仍由原生目标链判定。

C 代理逻辑时钟取已积分的原生有效 tick；RTS 辅助器只把 S 原有每 300 tick 的检查改为跨过一个五秒区间时检查一次，以适应原生可变步长，不增减出击门槛。准备关卡、记录器烟雾测试与未来 C 策略训练均独立标注，不能作为正式组间证据。桌面原生 state.tick 直接累加未截断的图形 delta，而物理 Time.delta 上限为 4 tick；两者与墙钟均保存，阶段时限及指标以真实参与更新的 Time.delta 积分计算。


原生规则调查已确认：三张评测图默认付费发射使用 Shard，基础单位上限 0、按核心可变，每兵种上限 8。Dagger 满血 150，最多 1,200 HP；14 个 Dagger 的假设不适用于这个原生上限。Nova 与重构厂均要求已占领 Fungal，因此不能作为首访的免费替代。保留 2,000 HP 门槛时，这属于真实科技/单位上限转化瓶颈，不能提高上限、赠送科技、改 HP 或偷偷降低出击阈值来消除。C 需照常运行并记录实际结果及 L 截断；它可能无法重现 S 的全路线完成方向。core-foundation 的额外研究和核心升级不在两套冻结布局内，不以加入这条新策略强行造出一致结果。调查文件 results/native-calibration-map-rules.csv 仅是规则检查，不是 C 样本。

C 正式前的客户端设置选择原生帧率上限30（所有组一致，480×360、软件渲染），以控制实时校准并发的CPU开销。仍使用原生 Time.delta 及原生4 tick上限，不改写模拟步长或快进；保留每帧实际delta、图形delta、native tick和墙钟，报告截帧比例与有效模拟/墙钟比。此前60帧烟雾测试不计正式样本；正式前的策略训练和准入还需使用这个设置。齐射和RTS的逻辑时钟来自有效模拟时间，不按渲染帧数计时。

补给代理只通过原生采矿、取货与转交执行。目标加工厂当前供电状态不低于0.85时，不以反复补满发电机阻塞真实原料补给；不足时才优先给同网原生燃烧发电机运输实际煤炭。这是准备与校准合法适配的共同补给顺序，不改电网数值或物资。该版本在正式C前训练、冻结，所有组一致。

确定性验收范围必须如实区分：S固定步长通过逐字节重复和观察开关不变性检查；C使用原生实时可变帧，未获得这两项逐字节证明，存在帧调度差异。因此C不作为S的确定性基准，不与S合并样本量；对题目全局确定性要求的这一适用限制须在报告中明确，不能用“正式准入”字样冒充已通过相同验收。

实际训练覆盖范围：两套原生训练均在A阶段失守，记录、库存和费用校验通过；它们没有获得B/C阶段或首访Fungal分支的完整实战训练证据。首访科技与单位上限来自原生规则读取和源码检查，实际到达、执行分支与成败必须由正式C日志单列确认。不得将A阶段流程验收表述为后续阶段已通关或已验证有效。
